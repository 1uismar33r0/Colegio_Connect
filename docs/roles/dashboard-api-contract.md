Generated `/v3/api-docs` is the machine-readable authority.

All five routes require an active server session. Student activity requires a current, verified UPRM member with global STUDENT role. Office and company data require current verified membership or the pending-owner link described below. The review queue requires current global MODERATOR authority. Persisted roles and account status are rechecked, so a revoked or suspended session loses access. Errors use `application/problem+json` with 401, 403, 400, or 409 as appropriate.

| Route | Body and query | Data rule |
| --- | --- | --- |
| `GET /api/listings/feed` | `FeedItem[]`; optional `keyword`, `type`, `field`, `page=0`, `size=20` (1–100) | Explicitly PUBLIC, PUBLISHED, unexpired listings from a current verified publisher with an eligible institutional role or approved company role. Posted time then ID descending. The array is one page; the current Luis client requests only the first page. |
| `GET /api/me/activity` | `{activeResponses, saved}` | Counts ACTIVE response rows and saved-listing rows owned by the authenticated student. It accepts no user ID. |
| `GET /api/institution/overview` | `{stats:{published,newResponses,drafts},recent:[...]}`; optional `organizationId` | One eligible membership can be inferred; more than one returns 409 until an ID is selected. Counts belong to the chosen office/department. `recent` is capped at 10, newest creation time then ID. Draft `newResponses` is null. Expired published rows display as CLOSED and are excluded from the published count. |
| `GET /api/company/dashboard` | `{stats:{activeListings,responses,profileStatus},active:[...],attention:{newResponses}}`; optional `organizationId` | Approved COMPANY members see their selected company's records. A verified external owner linked in `company_application_owners` to a pending company sees only a read-only `PENDING_APPROVAL` summary. More than one eligible organization requires an ID. The current external registration flow does not populate this ownership link. |
| `GET /api/admin/review-queue` | `{stats:{awaitingReview,reportedListings,pendingVerification},items:[...]}`; optional `page=0`, `size=20` (1–100) | Pending external companies and distinct listings with open reports, ordered by receipt time then ID descending. `pendingVerification` equals pending company profile checks from the same approval queue; no separate verification queue is claimed. Reporters and report details are omitted. Historical non-UUIDv7 organization rows may have `receivedAt: null`. |

The six supported opportunity codes are `JOB`, `INTERNSHIP`, `COOP`, `RESEARCH_POSITION`, `RESEARCH_PARTICIPATION`, and `CAPSTONE`. Responses use the labels `Job`, `Internship`, `Co-op`, `Research position`, `Research participation`, and `Capstone sponsorship`. Filters accept those labels or canonical codes. Luis's wireframe `Event` option and fixture have no approved category and must be removed. `field` is a case-insensitive exact match; keyword uses PostgreSQL full-text search. A missing result is a real empty query result, not a demo record.
