## Approved listing foundation

V6 creates minimal `capstone_teams(id,name,owner_user_id)` and `listings`. A listing has a UUID ID, publishing user, exactly one organization or capstone team owner, one of six opportunity categories, title, summary, status, trust label, display-only tags, and creation/publication/closing timestamps. Database CHECK/FK rules enforce the owner shape, student-team `CAPSTONE` category, and permitted trust-label/owner combinations. The feed rechecks the current publisher role, account and organization approval. A future write service must derive the trust label from those server-side facts; no listing write API is added here. Team membership and sponsorship remain Issue #48. `visibility` and `field` are absent. V7 saved/response and V8 report/pending-owner tables remain intact.

The six categories are `JOB`, `INTERNSHIP`, `COOP`, `RESEARCH_POSITION`, `RESEARCH_PARTICIPATION`, `CAPSTONE`, returned as `Job`, `Internship`, `Co-op`, `Research position`, `Research participation`, `Capstone sponsorship`. The three `sourceLabel` values are `Verified UPRM institution`, `Approved external company`, and `Verified student project`. Filters accept those labels or canonical underscore codes. `keyword` uses PostgreSQL full-text search. `organizationId` matches only organization-owned rows. Unknown `field` returns a structured 400, so Luis must remove his old field control. `Event` is not an approved category and returns 400.

`deadlineOnOrBefore=2026-11-10` means the inclusive November 10 calendar date in `America/Puerto_Rico`: the SQL bound is `closes_at < 2026-11-11T04:00:00Z`. Expiry is checked independently at the request's current instant. Published rows must have a non-null closing time; drafts may omit it and do not appear in the feed. The server's default time zone does not change the filter. `category` and `type` may both be sent if they resolve to the same category; a conflict returns 400. Remove `type` only after Luis migrates and the team approves removal.
