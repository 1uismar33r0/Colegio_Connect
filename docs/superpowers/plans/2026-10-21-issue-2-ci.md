# Issue #2 CI and Dependabot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the first secure CI gate and applicable Dependabot configuration for Colegio Connect.

**Architecture:** One GitHub Actions workflow separates backend verification from container verification and joins them through a stable `CI Gate`. Dependabot monitors only package ecosystems that currently have real manifests; frontend automation is added after Issue #13.

**Tech Stack:** GitHub Actions, Eclipse Temurin 25, Maven Wrapper 3.10.0, Docker/Compose, Dependabot.

**Spec:** `docs/superpowers/specs/2026-10-21-issue-2-ci-design.md`

## Global Constraints

- Do not modify backend, database, frontend, or Issue #6-owned source files.
- Use Java 25 and Maven `verify`; do not reproduce Testcontainers database setup in CI.
- Workflow token permissions are `contents: read` only.
- Pin every referenced action to a verified full commit SHA.
- Run CI on every branch push and every pull request targeting `main`.
- Do not add frontend checks, npm Dependabot, GHCR publication, deployment, or branch protection.
- Retain the main-branch Docker image artifact for seven days.

## Review Focus

- A failed or cancelled backend/container job must make `CI Gate` fail rather than pass or skip.
- Pull requests must never execute with write permissions or access deployment secrets.
- Testcontainers tests added by Issue #6 must be discovered naturally by Maven `verify` on the hosted Docker runner.
- The image artifact must upload only for a push to `main`, while the Docker build still runs on pull requests.
- Required checks must not use workflow-level path filtering or unstable duplicate job names.
